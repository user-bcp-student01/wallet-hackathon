# HU-01 - Onboarding guiado de wallet para el MVP

## Veredicto
**Usable con ajustes.** El alcance delimita la demo, sus resultados KYC simulados y la métrica de duración. Antes de implementar, deben concretarse los pasos y campos obligatorios y confirmarse el contrato del mock y el esquema de eventos.

## Contexto
El MVP busca validar un onboarding guiado para personas de 18 a 21 años en Perú que aún no han sido bancarizadas, mediante una interfaz web responsive para smartphone. La aplicación implementa la lógica propia del onboarding y consume el mock de pruebas para KYC y OTP; no se realizan operaciones financieras reales.

La referencia de producto es reducir el tiempo mediano de 8 a 3 minutos. La demo mide el tiempo del flujo de onboarding, pero no valida impacto de lanzamiento ni mide MAU o CAC.

## Ajustes necesarios
- Definir la secuencia exacta de pasos y sus campos obligatorios de acuerdo con el alcance aprobado; no inferir requisitos KYC.
- Usar `docs/openapi.json` como contrato del mock para KYC y resolución de verificaciones pendientes. El backend valida localmente el OTP fijo `123456` de la demo; no se envía al mock, no se envían SMS y no se usan datos personales reales. No inventar rutas, payloads ni respuestas del mock.
- Precisar el esquema de los eventos de inicio, finalización de cada paso y cierre, incluidos los datos mínimos necesarios para calcular la duración.
- Usar únicamente datos de prueba `TEST`, incluido el número de celular. El OTP es simulado: no enviar SMS ni usar números o documentos personales reales.
- Mantener separados el tiempo de revisión KYC y el tiempo hasta la activación; ninguno forma parte de la duración del flujo del usuario.
- Tratar los 3 minutos como referencia de producto, no como impacto productivo que deba demostrarse en la demo.

## Criterios de aceptación
- La interfaz responsive permite identificar la secuencia de pasos y el avance actual.
- Si faltan datos obligatorios o son inválidos, el flujo bloquea el avance y muestra cómo corregirlos.
- El usuario puede verificar un celular de prueba mediante OTP simulado, sin enviar SMS reales.
- El onboarding presenta los resultados `APPROVED`, `MANUAL_REVIEW` y `REJECTED` según la respuesta del mock. `APPROVED` activa la wallet; `MANUAL_REVIEW` queda pendiente y puede resolverse mediante el mock; `REJECTED` muestra el estado correspondiente.
- Se registran los eventos de inicio, finalización de cada paso y cierre del flujo.
- La métrica de duración va desde el inicio del onboarding hasta el envío correcto de los datos de todos los pasos. El reporte distingue esa duración del tiempo de revisión KYC y del tiempo hasta la activación.
- La demo no procesa pagos ni valida métricas productivas de MAU o CAC.

## Evidencia esperada
- Pruebas del avance guiado, validaciones y mensajes de corrección.
- Pruebas de los resultados KYC `APPROVED`, `MANUAL_REVIEW` y `REJECTED`, incluida la resolución de revisión manual mediante el mock.
- Pruebas del OTP simulado y evidencia de que no se envían SMS ni se usan datos personales reales.
- Pruebas de registro de eventos y del cálculo de duración, verificando que excluya los tiempos de revisión KYC y activación.
- Comandos reproducibles y resultados de las pruebas; no presentar pruebas propuestas como si ya se hubieran ejecutado.
